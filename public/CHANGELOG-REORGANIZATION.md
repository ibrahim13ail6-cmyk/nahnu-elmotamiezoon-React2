# تقرير إعادة تنظيم المستودع

- التقنية المكتشفة: صفحات HTML ثابتة، CSS، JavaScript، Firebase Authentication/Firestore، وواجهة serverless تحت `api/`.
- نُقلت ملفات CSS إلى `assets/css/`، وملفات JavaScript إلى `assets/js/`، وملفات PDF التسعة إلى مجلدات المادة داخل `assets/pdfs/`، ومقاطع MP4 الأربعة إلى `assets/media/video/`.
- نُقل الشعار الأصلي إلى `assets/images/logo.jpg`.
- نُقلت الصور التعليمية التي يشير إليها الكود (66 صورة) إلى `assets/media/images/` حتى لا تتعطل شرائح الدروس والمحتوى التعليمي.
- حُذفت 88 صورة غير مشار إليها من ملفات HTML/JS/CSS. لم تُحذف الصور التعليمية المشار إليها لأن ذلك كان سيكسر محتوى المنصة دون بديل مكافئ.
- حُدثت مسارات HTML وJavaScript وCSS والصور وPDF، وأُصلح رابط favicon الوهمي في الصفحة الرئيسية.
- أضيف هذا التقرير و`README.md`، وتم تحديث ملف «اقرأني.txt» للإحالة إلى README.

## التحقق المنفذ

- فحص سلامة أرشيف المصدر: ناجح.
- فحص نحو 36 ملف JavaScript باستخدام `node --check`: ناجح، دون أخطاء صياغة.
- التحقق من المسارات المحلية داخل صفحات HTML: لا توجد مسارات مفقودة.
- التحقق من أسماء الصور المشار إليها: لا توجد صور مفقودة.
- التحقق من ترويسة ملفات PDF التسعة: كلها ملفات PDF صالحة من حيث الترويسة.

## بيانات حساسة

لم يُعثر على كلمات مرور أو مفاتيح خاصة أو مفاتيح خاصة بصيغة PEM في الملفات المفحوصة. يوجد Firebase Web API key داخل إعدادات العميل في `assets/js/core.js` (وملف نسخة أخرى موجود في المستودع). هذا النوع من المفاتيح يُستخدم عادةً لتعريف مشروع Firebase في واجهة الويب وليس سرًا بحد ذاته؛ يجب تأمين الوصول عبر Firebase Security Rules وقيود Authentication، وعدم وضع أسرار خادم في ملفات الواجهة.

## حدود الاختبار

تم إجراء فحوصات ساكنة فقط. لم أشغّل الموقع مع Firebase أو أختبر تسجيل الدخول والتفاعلات في متصفح حي؛ لذلك لا أؤكد سلامة الوظائف المتصلة بخدمات خارجية وقت التشغيل.
